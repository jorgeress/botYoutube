# Script Template: Faceless Stickman Channel (Structured Beat Format)

Paste this entire prompt into the chat model you write scripts with, or use it through
`prompts/generate.md`.
You write the script as **structured beats**. Each beat has two layers:
- **Catalog fields** (`shot/char/pose/bg/…`), a small closed vocabulary that gives the
  channel consistency, per-segment continuity, and lets the linter validate the script.
- **`desc:`** one plain-English sentence describing the literal scene. This is the layer
  the image model (Nano Banana) actually draws, so it is the most important field.

The images are generated by **Nano Banana (Gemini 2.5 Flash Image)**, a strong model that
follows rich natural language and keeps a consistent character from a reference image. So
unlike the old Flux setup, you are NOT limited to 3-4 keywords, you describe a real scene
in `desc:`. The job is to describe **one clear, single, frozen moment** well (see DESC rules).

---

## YOUR REQUEST

Write a YouTube script for a faceless animated stickman channel.

- **Topic:** [TOPIC HERE]
- **Niche / tone:** [e.g. educational explainer, science, psychology, history]
- **Duration:** Quick test = 12-18 beats. Production = 85-105 beats. (See Duration Guide.)
- **Language:** **English** (narration and all `text:` values, always).

---

## THE FORMAT (mandatory: the pipeline parses this exactly)

```
TITLE: [Compelling title, max 60 chars, ASCII only]

NARRATION:
[SEGMENT 1]
(shot: medium | char: 1, surprised | pose: standing | bg: plain-white | desc: the surprised stickman holds a handle-less coffee mug, one detached curved handle resting on the floor below)
One narration sentence that matches the fields above.

(shot: text-frame | text: 'STATUS QUO BIAS' | desc: a small stick figure standing planted in place behind the text)
Scientists call this the status quo bias.

[SEGMENT 2]
(shot: diagram | left: question-mark | right: lightbulb | arrow: right yellow | bg: plain-white | desc: a question mark on the left, a glowing lightbulb on the right, one yellow arrow pointing from left to right)
A simple question is what turns into a real discovery.
```

- One `(fields)` line + the narration below it = one **BEAT** = one image on screen.
- One beat = one sentence. The image changes every ~3-5 seconds.
- Fields are `key: value` separated by `|`. Use only the keys and catalog values below.
- Multi-word values are hyphenated: `red-X`, `cracked-sun`, `open-book`, `lab-floor`.
- New `[SEGMENT N]` when the topic or location shifts.
- Hook hard in beat 1. Strong closing line in the last beat.

## SHOT TYPES (the `shot:` field, required, picks the fields you may use)

| `shot:` | What it is | Fields you may use |
|---|---|---|
| `text-frame` | A text card with a small illustration | `text:` `desc:` |
| `diagram` | Cause→effect, no character | `left:` `right:` `arrow:` `bg:` `labels:` `desc:` |
| `wide` | Full scene / establishing | `char:` `pose:` `prop:` / `props:` `time:` `place:` `bg:` `desc:` |
| `medium` | **Default.** Character + one prop | `char:` `pose:` `prop:` / `props:` `time:` `place:` `bg:` `desc:` |
| `close-up` | Hands or a single object | `char:` `pose:` `prop:` / `props:` `time:` `place:` `bg:` `desc:` |

Every beat should carry a `desc:` it is the field that makes the image match the words.

**ONE CLEAR MOMENT (most important):** describe a single focused scene, one main subject
plus at most 2-3 related objects. Nano Banana handles richer scenes than the old Flux setup,
so the scene lives in `desc:`; `pose:` and `prop:` are now secondary hints for consistency,
not the thing that gets drawn. Still, cramming many things makes clutter, keep it to one
readable moment. (`props:` is capped at 2 by the linter.)

## THE CATALOGS: pick values only from these lists

### `desc:` the literal scene (THE most important field for image quality)
A short English clause describing **exactly what is happening in this frame**: the
specific objects and the single action, lifted from the narration. This is what makes
the image actually illustrate the sentence (a mug with its handle off, a phone falling)
instead of a generic stickman pose. Add it to **every beat**, scene, diagram, and
text-frame.

- **Describe the END STATE as a static photo, never the action.** This is the #1 rule for
  Nano Banana: it is literal and additive, so any verb of change makes it draw BOTH states
  and duplicate the object (a mug with its handle AND a second falling handle).
  - ✗ `the mug's handle snapped off and is falling away` → draws two handles
  - ✓ `a handle-less mug in his hand, with one detached curved handle resting on the floor below`
  - Ban transition verbs in `desc:`: *snapping, falling, sliding off, coming apart, splitting,
    separating, peeling, lifting away, popping out, shedding, breaking.* Replace each with the
    finished position: *split / detached / lying loose / gaping open / resting separately.*
- **Count every object explicitly:** "one mug", "a single windshield", "two halves". The model
  draws what you count.
- **Place detached parts as their own single object** in a definite spot ("on the floor below",
  "beside his foot"), so the model puts it there instead of duplicating the whole thing.
- **One clause, ~12-25 words.** The `shot/char/pose/bg` fields still set framing, character and
  setting: `desc:` adds the specific objects and their finished arrangement on top.
- **Diagram `desc:`** restates the left→right relationship as a static layout.
- **Text-frame `desc:`** describes one small illustration to sit under the big text.
- Plain English, no blacklisted words, no em-dashes.

The closed fields below (`char/pose/emotion/prop/bg/...`) are still required, they give
consistency, continuity and validation. `desc:` is the literal layer on top of them.

### `char: <count>[, <emotion>[, costume: <costume>]]`
- count: `0`, `1`, or `2`. **Never more.** A crowd is `bg: crowd`, not many characters.
- emotion: `neutral` · `worried` · `surprised` · `strained` · `happy` · `curious` · `sad`
- costume (optional): `none` · `lab-coat` · `tie` · `chalk-teacher` · `cave-person`
  - Use `costume: lab-coat` when narration mentions researchers/scientists/MIT/lab.
  - **No round glasses**: they distort the stickman face; lab-coat alone is enough.
- You do **not** describe what the stickman looks like, CHARACTER ANCHOR is auto-injected.

### `pose:` (only when char ≥ 1)
`standing` · `pointing-right` · `pointing-left` · `arms-crossed` · `arms-raised` ·
`hands-on-hips` · `head-in-hands` · `thinking` · `holding-object` · `sitting-desk` ·
`lying-bed` · `walking` · `running` · `jumping` · `reaching-up` · `kneeling` · `falling`

**POSE-EMOTION HINTS: natural pairings (the linter only warns, never blocks):**
With Nano Banana any pose+emotion combination renders fine, so this is just a guide to the
most natural pairings. Use a different emotion freely when the narration calls for it
(e.g. `surprised` + `head-in-hands` for shocked dismay).

| Pose | Natural emotions |
|---|---|
| `thinking` | neutral, curious, worried |
| `head-in-hands` | strained, worried, sad |
| `arms-raised` | happy, surprised |
| `arms-crossed` | worried, neutral, strained |
| `walking` | neutral, happy, curious |
| `sitting-desk` | neutral, curious, strained |
| `reaching-up` | happy, curious |
| `running` | worried, happy, neutral |
| `jumping` | happy, surprised |
| `standing` | any |
| `pointing-right/left` | neutral, happy, curious, surprised |
| `lying-bed` | neutral, happy, sad, strained |

### `prop:` (one prop) or `props:` (up to two, comma-separated)
Use `prop:` for a single prop. Use `props:` only when you genuinely need two.
names: `red-X` · `green-check` · `cracked-sun` · `bright-sun` · `thermometer` ·
`plant-pot` · `dead-plant` · `lightbulb` · `brain` · `coin` · `battery` · `clock` ·
`calendar` · `book` · `beaker` · `chalkboard` · `phone` · `door` · `arrow` · `globe` ·
`skull` · `droplet` · `ice-crystal` · `fire` · `gear` · `star` · `heart` ·
`arrow-up` · `arrow-down`
position: `left` · `right` · `above` · `below` · `held` · `floating-right` · `floating-left`

### `time:` (NUEVO: triggers sprite overlay, no Flux overhead)
`morning` · `afternoon` · `evening` · `night` · `none`
- `morning` → pipeline composites a sun sprite top-right. Do **not** also add `bright-sun` as a prop.
- `afternoon` → small clock sprite top-right.
- `evening` → Flux adds warm amber window light.
- `night` → overrides `bg:` to dark night sky.
- Rule: if narration says "morning", "wake up", "early in the day" → use `time: morning`.

### `place:` (NUEVO: PIL writes text on a Flux building sign)
`place: 'MIT'` · `place: 'HARVARD'` · `place: 'NASA'` · etc. (1-3 UPPERCASE words)
- Use when narration names a specific institution or city.
- The pipeline draws a blank building sign in Flux, then writes the place name in Caveat-Bold.
- Rule: if narration mentions "at MIT", "from Harvard", "NASA researchers" → `place: 'MIT'`.

### `bg:`
`plain-white` · `grass-sky` · `night` · `dark-stars` · `lab-floor` · `interior` ·
`prehistoric` · `space` · `crowd`

### `diagram` symbols (`left:` / `right:`)
`question-mark` · `lightbulb` · `brain` · `open-book` · `bright-sun` · `cracked-sun` ·
`plant` · `dead-plant` · `battery` · `clock` · `coin` · `globe` · `skull` · `droplet` ·
`ice-crystal` · `fire` · `gear` · `dna-helix` · `star` · `heart` ·
`arrow-up` · `arrow-down` · `arrow-left` ·
`number-0` · `number-1` · `number-2` · `number-3` · `number-4` ·
`number-5` · `number-6` · `number-7` · `number-8` · `number-9`

`arrow:` = `<direction> [color]` → direction: `right` (default) `left` `down` `up` · color: `red` (default) `green` `blue` `yellow`

`labels:` = `'LEFT LABEL','RIGHT LABEL'`, optional Caveat-Bold labels below each symbol.

### `text:` (only on `shot: text-frame`)
- `'EXACT WORDS'` in single quotes.
- **ALWAYS UPPERCASE. ≤ 4 words AND ≤ 15 characters per word.**
- ASCII only: A-Z, 0-9, `%`, space. No apostrophes, `&`, accents, or other punctuation.
- Lift the words straight from the narration (the exact concept name or number).

## THE 9 RULES (apply to every beat)

1. **Name it when you say it.** When the narration first names a concept (`called X`,
   `known as X`), that beat is a `text-frame` with `text: 'X'`, the exact name, never a paraphrase.
2. **One text element per beat.** Text lives only in `text-frame` beats. Never burn text into a scene.
3. **One prop per scene beat.** (The 4-element rule.) Use `props:` only when you genuinely need two.
4. **Emotion matches the narration tone.** Fear/threat → `worried`; effort/drain → `strained`;
   discovery/"it turns out" → `surprised`; comfort/routine → `happy`.
5. **Diagrams read left→right.** Cause/before on `left:`, effect/after on `right:`, `arrow:` always explicit.
6. **Continuity:** every beat in a segment shares the same `bg:` unless the narration changes location.
7. **Text-frame frequency:** at most one `text-frame` every 8-10 beats. They lose impact if overused.
8. **Blacklist:** never use the words `realistic`, `detailed`, `photo`, `3D`, `person`,
   `man`, `woman`, `human`. The character is always a `stickman` (handled by the fields).
9. **Sync the new fields:** add `time:` whenever narration mentions morning/afternoon/evening/night;
   add `place: 'NAME'` whenever narration mentions a named institution or city; add `costume: lab-coat`
   when narration mentions researchers/scientists/lab. Never add these for decoration, only when the
   narration explicitly triggers them.
10. **No em-dashes or double dashes.** Never use `, ` or `--` in narration. Use a comma or period
    instead. Em-dashes appear as `, ` in subtitles and sound broken.
11. **Text-frame narration must say the concept.** When a beat is `shot: text-frame | text: 'WORD'`,
    the narration sentence MUST say that exact word. `(text: 'PROCRASTINATION')` → narration says
    "Scientists call it procrastination..." Never just allude to it.
12. **Every beat carries a literal `desc:`.** One concrete clause of exactly what is in the frame
    (the real objects + single action from the narration), one frozen moment, no before/after,
    no duplicated objects. This is the field that makes the image illustrate the sentence.

## RETENTION ARCHITECTURE: 8-MINUTE VIDEO

This is how high-retention educational YouTube videos are structured. Use this as the skeleton.

### Beat 1: The Hook (most important beat in the video)
Start the viewer IN the middle of a relatable moment. Never introduce the topic from the outside.

| ✗ WEAK | ✓ STRONG |
|---|---|
| "Procrastination is a common problem." | "You told yourself you would start an hour ago, but here you are, still not starting." |
| "Today we discuss sleep." | "Last night you meant to sleep at 10. You looked up and it was 2am." |
| "This video is about habits." | "Every Monday you swear this week will be different. It never is." |

**Rule:** Beat 1 must start with "You" or put the viewer in first-person. Name the pain.

### Segment structure for 8 minutes (~90-100 beats)

```
[SEGMENT 1: HOOK + PROMISE] beats 1-5
  Beat 1: Start in medias res with "You", put viewer IN the scene.
  Beat 2: "And it is not just you, X% of people / every person who..."
  Beat 3: text-frame → THE CONCEPT NAME (first time it appears on screen)
  Beat 4: The counterintuitive premise: "It is not willpower / laziness / discipline, it is..."
  Beat 5: Promise: "By the end of this you will understand exactly why and have one fix."

[SEGMENT 2: THE SCIENCE / ROOT CAUSE] beats 6-20
  Introduce the hidden mechanism. Use diagrams and costume: lab-coat when citing research.
  End with a curiosity pull: "But here is the part nobody explains..."

[SEGMENT 3: THE MECHANISM / DEEPEN] beats 21-40
  Show HOW the cycle works. At least 1 diagram beat showing the loop.
  Introduce the counterintuitive twist (the thing most people have wrong).
  text-frame for the mechanism name (e.g., 'AVOIDANCE LOOP').
  End with: "And this is where most people are completely stuck..."

[SEGMENT 4: STAKES / COST] beats 41-55
  What is the real cost of NOT knowing this? Make it personal and concrete.
  Numbers and research help: "A 20-year study tracked 2,000 people..."
  End with: "The solution is simpler than you think, but it works for a reason..."

[SEGMENT 5: THE SOLUTION] beats 56-75
  Introduce the named technique / fix.
  text-frame → TECHNIQUE NAME (e.g., 'TWO MINUTE RULE').
  Step-by-step (use 3-beat triplet): what to do, why it works, the specific trigger.
  Diagram showing the new loop / mechanism.

[SEGMENT 6: PAYOFF + IDENTITY SHIFT] beats 76-90+
  Research backing: "Studies show that people who use this..."
  Practical application: exactly when/where/how to do it today.
  Reframe identity: "This is not about willpower, it is about knowing how your brain works."
  Final beat: arms-raised happy stickman, bright bg, strong closing line.
```

### Curiosity loops: end every segment with a pull

Every segment except the last should end on an open question or unresolved tension:
- `"But here is the part nobody explains..."` → lead into the mechanism
- `"And the reason comes down to one thing..."` → reveal in the next segment
- `"The solution is not what you expect..."` → create anticipation
- `"Here is where it gets surprising..."` → signal a counterintuitive turn
- `"Most people stop here, but there is one more piece..."` → keep watching

Build these into the LAST NARRATION LINE of each segment. They are the retention glue.

### Pattern interrupts: schedule

Every 8-12 beats, change the visual register to prevent the viewer from tuning out:
- Switch `bg:` (e.g., plain-white → lab-floor → interior → grass-sky)
- Insert a `diagram` beat to show a cycle or mechanism
- Insert a `text-frame` for the key concept name (max 1 per 8-10 beats)
- Switch stickman `emotion` from strained/worried to surprised/curious

## DURATION GUIDE

| Mode | Beats | Narration words | Runtime |
|---|---|---|---|
| **Quick test** | 12-18 | 120-180 | ~60-90 sec |
| Short demo | 25-35 | 300-400 | ~2.5-3 min |
| YouTube minimum | 65-80 | 800-950 | ~6.5-7 min |
| **Production** | 85-105 | 950-1150 | ~8 min |

One beat = one idea = one sentence (~10-15 words). If tempted to write two sentences after a
visual, split into two beats with two distinct beats instead.

## BEFORE YOU DELIVER: self-check

Re-read your **first 10 beats** and fix any that fail:
1. Does beat 1 start with "You" and place the viewer in a specific scene?
2. Does every beat start with a valid `shot:`?
3. Are all field values from the catalogs above (no invented poses/props/backgrounds)?
4. Does every scene beat have **at most one** `prop:` (or max two with `props:`)?
5. Is there **at most one** text element per beat, and only in `text-frame` beats?
6. Is every `text:` UPPERCASE, ≤4 words, ≤15 chars/word, ASCII only?
7. Does the `emotion` match the narration tone? Is the pose compatible with the emotion?
8. Do all beats in each segment share the same `bg:` (unless the location changed)?
9. No blacklisted words anywhere?
10. Did you add `time:`/`place:`/`costume:` wherever the narration explicitly triggers them?
11. Does each segment (except the last) end with a curiosity-loop pull line?
12. No em-dashes (`: `) or double dashes (`--`) in any narration line?
13. Does every `text-frame` narration say the concept word explicitly?
14. Does every beat have a literal `desc:` with concrete objects and one frozen moment (no before/after)?

Then scan the rest of the script for the same issues before finishing.
